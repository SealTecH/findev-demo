# Realtime Fintech Dashboard

Live metrics for fictional instruments. Market updates are generated by a Rust/WebAssembly module
running in a Web Worker, and the Angular UI displays the totals.

- Demo: https://findev-demo.vercel.app
- Repository: https://github.com/SealTecH/findev-demo

## Pages

- **Dashboard** has a table with one row per instrument: last price, bid–ask spread, cumulative
  volume, VWAP and order-book imbalance. It also shows the producer status, the run number, the
  amount generated, the actual and nominal rate, a Pause/Resume button and **Restart run**
  (a new run with the same settings: totals are cleared and generation starts). If the producer
  fails, an error message with Retry replaces the table.
- **Settings** is a form with three integer settings: instrument count (1–50), updates per batch
  (1–1000) and batch interval (50–2000 ms). Editing does nothing by itself. **Apply** starts a new
  run, clears the totals and starts generating even if the producer was paused.

On startup the app creates a paused run with the defaults (5 × 100 every 500 ms): the table shows
the instruments with no values yet, and Resume starts generating. Switching pages does not
interrupt the run or the pause.

## Requirements

- Node 24 (`.nvmrc`), npm.
- Rust stable with the `wasm32-unknown-unknown` target. `rust-toolchain.toml` installs both through
  rustup on the first build.
- `wasm-bindgen-cli` matching the version in `wasm/producer/Cargo.lock`:

  ```bash
  cargo install wasm-bindgen-cli --version 0.2.130 --locked
  ```

## Commands

```bash
npm ci
npm start              # dev server at http://localhost:4200
npm test               # unit tests (Vitest)
npm run build          # production build into dist/findev-demo/browser
npm run lint
cargo test --manifest-path wasm/producer/Cargo.toml
```

`npm start`, `npm test` and `npm run build` first build the Wasm module
(`scripts/build-wasm.mjs`). The JS glue goes to `src/app/producer/wasm-pkg/` and the `.wasm` file
to `public/wasm/`; both are generated and not committed.

## Architecture

```
Settings page ─ apply ─┐
Dashboard ─ pause ─────┤                         Web Worker
                       ▼                  ┌──────────────────────────────┐
              ProducerService ── start ──►│ ProducerEngine               │
              (one per app)   ◄─ snapshot ┤  timer → Wasm generate(n)    │
                       │                  │        → aggregate totals    │
     merge → scan(reduce) → signal        └──────────────────────────────┘
                       │
             rows, status, rates → pages
```

- **Rust/Wasm (`wasm/producer`)** keeps a random walk of prices and the order book for each
  instrument and returns a batch of updates as a flat `Int32Array`: 7 integers per update, prices in
  cents.
- **Worker (`producer-engine.ts`)** calls the generator on a `setTimeout` chain. Missed batches are
  not caught up, so a background tab does not get a burst afterwards. The worker adds each update
  to the totals (volume, notional) and posts one snapshot of the totals per batch. The main thread
  therefore receives at most one message per batch, whatever the batch size.
- **Main thread (`producer-service.ts`, `run-state.ts`)** merges commands and worker messages
  into one state with a pure `reduce`. Each run has a `runId`, and messages from a previous run
  are ignored. Retry recreates the worker, and the old one is terminated.
- **Metrics (`market/metrics.ts`)** are computed from the totals at display time. Money is kept in
  integer cents (notional is a `bigint`) and rounded only for display.

At 50 instruments × 1000 updates every 50 ms (20,000 updates/s) the main thread has no long tasks.

## Project layout

| Path                          | Contents                                                  |
| ----------------------------- | --------------------------------------------------------- |
| `wasm/producer/`              | Rust generator and its tests                              |
| `src/app/market/`             | Update decoding, aggregation, metrics, formatting         |
| `src/app/producer/`           | Settings schema, worker, protocol, state, ProducerService |
| `src/app/dashboard/`          | Dashboard page                                            |
| `src/app/settings/`           | Settings page                                             |
| `scripts/build-wasm.mjs`      | Builds Wasm and the JS glue                               |
| `scripts/vercel-install.sh`   | Installs Rust and wasm-bindgen on Vercel                  |

## Extending

- **New metric:** add an entry to `METRICS` in `src/app/market/metrics.ts` (id, header, format,
  computation from the totals). The table builds its columns from this list.
- **New setting:** add an entry to `SETTINGS_SCHEMA` in `src/app/producer/settings.ts` (label,
  hint, range, default). The form, validation and messages come from the schema. Then pass the
  value on to the worker or the generator where it is used.

## Deployment

Vercel builds every push (`vercel.json`): `scripts/vercel-install.sh` installs Rust and the
prebuilt `wasm-bindgen`, then runs `npm run build`. GitHub Actions (`.github/workflows/ci.yml`)
runs rustfmt, clippy, `cargo test`, lint, the format check, the unit tests and the build.
